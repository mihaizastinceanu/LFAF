## Theory

A **formal language** is a set of strings constructed from a finite alphabet according to specific rules. Its key components are:

- **Alphabet (Σ):** Set of valid symbols `{a, b, c, d}`
- **Non-terminals (Vn):** Symbols used to generate strings `{S, A, B}`
- **Grammar rules (Productions, P):** Define how symbols can be replaced
- **Start symbol (S):** Beginning of string generation

A **regular grammar** is a type of formal grammar where all production rules have a single non-terminal on the left-hand side and a terminal followed by an optional non-terminal on the right-hand side. Regular grammars are equivalent to **finite automata**, which can determine whether a string belongs to the language.

## Implementation Description

### Grammar Class
The `Grammar` class stores non-terminals, terminals, and productions. It contains a method `generateString()` which randomly applies production rules to generate valid strings. It also provides `toFiniteAutomaton()` to convert the grammar into an equivalent finite automaton.

### FiniteAutomaton Class
The `FiniteAutomaton` class stores states, alphabet, transitions, start state, and final states. Its method `stringBelongToLanguage()` checks if a given string can be generated by the automaton.

### Main Class
The `Main` class demonstrates the functionality by:
- Generating **5 valid strings** from the grammar
- Converting the grammar to a finite automaton
- Testing multiple strings for membership in the language

## Code Snippets

```java
public static void main(String[] args) {
    Grammar grammar = new Grammar();

    System.out.println("Generated strings:");
    for (int i = 0; i < 5; i++) {
        System.out.println(grammar.generateString());
    }

    FiniteAutomaton fa = grammar.toFiniteAutomaton();

    String[] tests = {"db", "dab", "daab", "bdab", "bdcba", "abc", "dd"};

    System.out.println("\nTesting strings:");
    for (String s : tests) {
        System.out.println(s + " -> " + fa.stringBelongToLanguage(s));
    }
}
```

## Conclusions

The implementation successfully demonstrates the relationship between regular grammars and finite automata.
The Grammar class encodes Variant 25's production rules (VN={S, A, B}, VT={a, b, c, d}) and generates valid strings
through random leftmost derivation. The toFiniteAutomaton() method converts the grammar into an NFA by mapping
non-terminals to states and production rules to transitions, with single-terminal productions leading to a FINAL
accepting state. The FiniteAutomaton class then validates strings using subset construction, maintaining the set
of active states across each input character. Testing confirmed that valid strings (db, dab, daab, bdab, bdcba)
are accepted and invalid ones (abc, dd) are correctly rejected, proving the automaton faithfully represents
the formal language defined by the grammar.
